# Хорошее ли вино

Streamlit-приложение к ДЗ-3: логистическая регрессия оценивает вероятность того, что вино получит оценку 7 и выше.
Модель в приложении не обучается: оно читает файлы, сохранённые ноутбуком.

```
wine_app/
├── app.py            # приложение
├── model.joblib      # пайплайн StandardScaler + LogisticRegression
├── config.json       # выбранный порог
├── test.csv          # тестовая выборка со столбцом target
├── requirements.txt
└── README.md
```

## Запуск

Нужен Python 3.12.

```bash
cd wine_app
python3.12 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

Приложение откроется на http://localhost:8501.

## Вкладки

- **Оценка одного вина** – 12 признаков (диапазоны и значения по умолчанию – минимум, максимум и медиана по `test.csv`), вероятность и решение при текущем пороге.
- **Модельные метрики** – матрица ошибок, precision, recall, F1, ROC- и PR-кривые с точкой текущего порога на тестовой выборке.
- **Пакетное предсказание** – CSV с признаками вин (без `target`) → таблица с вероятностью `proba` и решением `good`, кнопка скачивания.
- **Что выучила модель** – коэффициенты логистической регрессии после масштабирования.

Порог задаётся ползунком на боковой панели и действует на всех вкладках. По умолчанию – порог из `config.json`.

## Кэширование (задание 4.5)

Streamlit выполняет `app.py` заново при каждом действии пользователя.

**Почему модель – `st.cache_resource`.** Этот кэш отдаёт всем вызовам и всем пользователям один и тот же объект: модель читается с диска один раз на весь сервер. Так можно, потому что модель в приложении не меняется – мы только вызываем `predict_proba`. `st.cache_data` отдаёт каждому вызову копию результата, а копия модели – это снова сборка объекта из байтов на каждом перезапуске.

**Почему таблицы – `st.cache_data`.** `test.csv` и вероятности на тесте – данные. Каждый вызов получает свою копию, поэтому код одной сессии не испортит кэш остальным. Вероятности считаются один раз: у `test_proba(_model, X)` подчёркивание говорит Streamlit не хешировать модель, ключ кэша – только `X`. При движении ползунка меняется только сравнение `proba >= threshold`, `predict_proba` заново не вызывается.

**Что будет без декоратора.** `joblib.load` выполнялся бы при каждом движении ползунка и каждом изменении поля: файл заново читается с диска, модель собирается заново. Приложение работает медленнее, хотя модель не менялась.

Обратная сторона кэша: если заменить `model.joblib`, приложение продолжит работать со старой моделью, пока сервер не перезапущен или кэш не очищен (клавиша `C` на странице).

Путь к файлам строится от папки с `app.py` (`Path(__file__).parent`), поэтому приложение находит файлы, из какой бы папки его ни запустили.

## Модель

Обучена на официальном `wine_quality.csv` из репозитория курса. В `test.csv` — 1950 строк. Порог 0.27 выбран на валидации. На тесте: precision 0.475, recall 0.637, F1 0.544.
